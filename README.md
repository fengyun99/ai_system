# AI 智能客服系统（Python 全栈演示版）

> 面向公积金业务的智能客服演示系统：**FastAPI + LangGraph Agentic RAG + MCP 工具面 + Elasticsearch 混合检索 + React 管理端**。
> 由原 Java（编排层）+ Python（原子能力层）双服务架构收敛为单 Python 服务全栈实现，加密体系与数据库口令协议与原 Java 侧逐位兼容。

---

## 一、技术栈

| 层 | 选型 |
|---|---|
| 后端 | Python 3.12 · FastAPI · LangGraph（Agentic RAG 状态图）· LangChain · MCP 官方 SDK（FastMCP）· SSE 流式 |
| 检索 | Elasticsearch 8（BM25 + kNN 双路召回 → RRF 融合 → 重排模型精排）· jieba 分词 |
| 联网 | 自建联网检索服务（SearXNG 协议兼容，Bing+搜狗多引擎聚合，本仓 search_service）· 判官不足判定兜底 |
| 存储 | MySQL（Tortoise ORM，RBAC 六表 + 对话/轮次/阶段审计三表 + 知识 + 工具）· Redis（停止信号/在线态，可缺省） |
| 模型 | model-config.json 配置驱动（**DeepSeek 单一供应商**：对话 + 向量化同 key；换模型改配置不改代码；重排不可用自动回退 RRF） |
| 安全 | SM3 国密口令（`$1a` 版本号 + 自加盐双重摘要，与原 Java 完全一致）· SM4-CTR 配置加密（`Enc[...]`）· JWT(HS512) · RBAC + 数据范围 |
| 前端 | React 18 · TypeScript · Vite · Tailwind CSS · Redux Toolkit · React Router · shadcn/ui 风格组件 · marked + DOMPurify |

## 二、核心特性

1. **LangGraph Agentic RAG 全管线**（每个节点=一个登记阶段，前端实时展示）：
   ```
   意图识别 ─┬─ business ─┬─ 命中办理流程 → 只做办理推荐（不查数据/不做政策长回答）
             │            └─ 未命中（查询类）→ MCP 工具循环（list_tools → bind_tools → 多轮推理）
             ├─ chitchat → 直接生成
             ├─ off_topic → 无关话题拒答（只能问公积金 + 引导转人工）
             └─ rag → 区域识别 ─┬─ 外地区 → 联网检索（自建服务）→ 生成
                                └─ 问题分类 ∥ 问题分化（并行）→ 混合检索(BM25+kNN→RRF)
                                   → 重排序（失败回退融合序）→ 材料充分性判断（快速判官）
                                      ├─ 充分 → 直接回答
                                      └─ 不足 → 联网检索（自建服务，来源切换为联网并混合展示）
                                                 ├─ 取到材料 → 生成
                                                 └─ 未取到/联网关闭 → 拒答（暂不支持 + 转人工引导）
   ```
2. **流程全程登记**：`turn`（轮次汇总：意图/区域/主题/快照/token/首字延迟/总耗时）+ `turn_stage`（阶段流水：输入输出 JSON / 模型 / token / 耗时）；管理端可回放任意一轮。
3. **多租户与权限**：机构树（dept_no）为租户轴——检索可见性=本机构 ∪ 祖先链公开知识（兄弟互不可见）；RBAC 角色-菜单-按钮权限 + 数据范围（全部/本部门及以下）；读范围/可写集分离。
4. **MCP 工具面**：官方 SDK FastMCP 同进程 streamable-http 服务（`/mcp`），工具登记表按部门下发（本部门+共享），Agent 侧真实走 MCP 协议发现与调用；工具结果敏感字段脱敏。
   **三要素（身份证号/手机号/姓名）随登录态由 mock 数据绑定**——查询与办理自动使用，不向用户索要、界面不明文展示（`app/mock_data.py`）。
5. **知识入库链**：问答/文档/常识统一管理 → 切块 → 向量化 → ES 写入；未同步行显形可重试，支持批量同步与全量对账。
6. **自建联网检索（不依赖模型厂商联网）**：本仓 `search_service` 提供 SearXNG 协议兼容的检索服务
   （多引擎聚合 + 去重轮转 + 位次分），LLM 仅对检索材料做归纳；换真 SearXNG 只需改 `websearch.base_url`。
7. **业务流程引擎与办理门控**：流程定义（form → confirm → auto → end 线性步进）+ 实例状态机；
   办理中**禁止提问**（前端禁用输入 + 后端 409 双重门控），完成或取消后自动恢复问答。
   流程交互**只登记在流程表**（flow_instance.steps，含每次提交/校验失败尝试），**不进对话流**——
   对话框只呈现卡片：办理中为可交互表单（步骤按**用户交互步**计，如 1/3），
   结束后切换为**最后一态的表单数据**（紧凑三段式：办理信息 / 信息确认 / 办理结果含受理单号），
   历史回看同形态还原；所有敏感字段（卡号/证件号/手机号）**脱敏展示**。
8. **办理流程走独立业务服务（与 MCP 工具面分离）**：`app/biz_service.py` 模拟业务系统
   （账户核验 → 额度校验 → 业务受理返回受理单号），流程引擎只调用该动作集；
   MCP 工具面仅服务问答场景，两者动作集零交集（验收项已断言）。
9. **模拟后端表单校验**：身份证号/银行卡号/金额按规则做后端校验（卡号须为缴存人名下登记卡、
   金额 ≤ 可提取额度等），失败时**字段级红色报错且不推进节点**，修正通过后才走下一步；
   Mock 数据与报错文案见 [docs/mock-data.md](docs/mock-data.md)。
10. **拒答与转人工**：判官判定"不能回答"时明确回复 **当前内容暂时不支持回答** 并引导 **转人工**
   （门户右下角转人工入口 → 后端登记 `intent=handoff` 轮次，审计留痕）；无关公积金的问题在意图层直接拦截拒答。
11. **来源可点击与混合展示**：引用来源按类型渲染——📖 知识库来源点开弹层查看原文（含所属机构）、
   🌐 联网来源新窗口打开原文；联网补充场景下知识库与联网来源**混合展示**（联网为主 + 知识库保留），
   机构一律显示**机构名称**（如"福州市住房公积金中心"）而非编号。
12. **推荐体系与真实系统一致**：回答后推荐 **可能相关问题**（点击即追问）与 **可能办理的业务**；
    办理推荐区分 **简单业务（流程引擎嵌入会话办理）** 与 **复杂业务（跳转业务系统页面，如购房提取需提交材料）**。
13. **断线重连（断线≠停止，整轮回归）**：客户端断开/刷新不影响服务端执行（后台继续缓冲并算完落库）；
    重连时 `GET /api/chat/resume/{turn_id}` **从缓存从头回放整轮事件**，前端先重置该轮再整体重绘
    （按 turnId 定位渲染，不在半截内容上追加，杜绝格式错乱）；仅显式停止（`/chat/stop`）才中断置 interrupted。
    前端三层保障——会话记忆（刷新自动回到最近会话）、末轮生成中自动整轮回放、
    15s 空闲看门狗（假死连接自动查状态转回放或回读历史）。
14. **加密与原 Java 互认**：①登录口令协议逐位一致（同账号在原 Java 库可直接登录）；②配置敏感值 `Enc[...]`（SM4-CTR）密文互认，明文填写首次启动自动加密回写。

## 四、快速启动

> **Docker 一键启动**：`docker compose up -d --build`（详见 [docs/deploy.md](docs/deploy.md) 第七章）

```bash
# 0) 前置：MySQL / Elasticsearch / Redis 已在本机运行（见 config/app.yml）
#    首次：初始化数据库 + 种子 + 知识入库 ES
cd fastapi-app
uv sync                                        # uv 管理依赖（推荐；清华源已配在 pyproject.toml）
# 备选（无 uv 时）: python -m venv .venv && .venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python.exe scripts/init_db.py            # 追加 --reset 可重置

# 1) 启动后端（127.0.0.1:9310，MCP 同进程挂载 /mcp）
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 9310

# 2) 启动自建联网检索服务（127.0.0.1:8888；也可换成 docker 版真 SearXNG）
.venv/Scripts/python.exe -m uvicorn search_service.main:app --host 127.0.0.1 --port 8888

# 3) 启动前端（127.0.0.1:5173，代理 /api 与 /mcp 到后端）
cd ../web && npm install && npm run dev

# 4) 一键进程完整性验收（45 项：知识/跨库/联网/判官/流程办理/门控/取消/拒答/转人工/审计）
.venv/Scripts/python.exe scripts/integrity_check.py
```

演示账号与演示问题清单见 **[docs/demo-guide.md](docs/demo-guide.md)**（账号、Mock 用户、按主题的演示问题与十分钟演示动线）。

## 五、面试演示脚本（10 分钟）

1. **登录**（`/login`）——打开浏览器 Network：口令在发送前已做 **SM3 国密摘要**（明文不出浏览器）；后端按
   `$1a + sm3(sm3(P+"{"+P+"}"))` 校验，与原 Java 库同账号可直接互认登录。
2. **问答门户**（`/portal`）——问「福州公积金贷款最高能贷多少？多孩家庭有上浮吗」：
   - 观察回答上方**纵向处理流程**自上而下逐节点点亮（意图识别→区域识别→问题分类→问题分化→混合检索→重排序→生成），每个节点带语义摘要（主题/子查询/BM25+kNN 命中数/融合与重排保留数）；
   - 回答下方的**引用来源**展示跨机构知识（35002 本地 + 35000 省级公开，附重排分数）——多租户祖先链可见性；
   - 侧栏会话历史可回放。
3. **业务办理 → MCP 工具**——问「帮我查一下我的公积金账户余额，身份证号350102199001011234」：
   - 回答前出现**工具卡片**：工具名 `query_account_balance` + 实参 + 可展开的脱敏返回值（`350***********1234`）；
   - 该轮阶段流水含 `工具发现(list_tools)` 与 `工具调用:xxx` 两行。
4. **联网问答（自建检索）**——问「北京的公积金租房提取额度是多少」：外地区自动转**自建联网检索服务**
   （阶段线出现 🌐 联网检索），回答引用政府/权威站点并给出可点击来源；问「公积金贷款提前还款需要支付违约金吗」演示
   **判官判定知识不足 → 联网兜底**。全部材料来自自建服务，未使用任何模型厂商的联网能力。
5. **拒答与转人工**——问「帮我写一段 Python 排序代码」（无关话题）：意图层直接拒答"只能回答与住房公积金相关的问题"；
   问「公积金贷款提前还款需要支付违约金吗」：判官判定知识不足 → 自动联网补充作答；
   若联网关闭/未命中，则回复"当前内容暂时不支持回答"并引导转人工（右下角 🎧 转人工可提交转接请求并审计留痕）。
6. **来源与推荐**——回答下方：📖 知识库来源可点开查看原文（显示所属机构）、🌐 联网来源可跳转原文；
   混合场景两类来源同时展示并标注数量；「您可能还想问」点击即追问；
   「相关业务办理」区分 ▶ 在线办理（流程引擎嵌入）与 🔗 跳转业务系统（复杂业务）。
7. **业务办理与门控**（完整流程任务）——
   - 问「我要办理租房提取」→ 回答下方出现 **▶ 可直接办理** 入口（办理推荐）；
   - 点击进入流程：聊天卡片 1/5 填写提取信息 → 2/5 收款账户 → 确认页 → **系统自动核验（MCP 工具，脱敏返回）** → 完成；
   - 办理全程**输入框禁用 + 横幅提示**（后端同时返回 409，双重门控）；点「取消流程」可随时退出；
   - **故意填错**：身份证号填 `350199199901019999`、卡号填 `1234` → 字段下方红色 ⚠️ 报错且**停留原节点**；
     卡号填他人卡 `6222020000000000000` → "卡号与缴存人 陈测试 的登记账户不一致"；修正后（`350102199001011234` /
     `6222021234567890123`）才进入确认页；金额超余额同样被拦（Mock 数据见 docs/mock-data.md）；
   - 确认后自动走**业务系统三项校验**（账户核验 / 额度校验 / 受理并返回受理单号）；
   - 完成或取消后问答立即恢复；全程交互照常进轮次审计（intent=flow）；
   - **历史还原**：切到其它会话再切回本会话（或刷新），流程卡片按当时的形态完整重建——
     步骤进度、已填值、业务校验结果、字段报错、完成/取消状态一应俱全。
8. **管理后台**（`/manager`，fzzx 账号）：
   - **仪表盘**：轮次/token 入出/平均首字延迟/平均耗时/意图与主题分布（中文标签后端单一来源）；
   - **轮次审计**：任意轮次的阶段流水回放——每阶段模型名、token、耗时、输入输出 JSON（token 与耗时只在此展示，门户不展示）；
     过滤支持 时间范围/机构/来源(门户·开放接口)/意图/状态/关键词，并可一键 **导出意图识别数据 / 对话QA（xlsx，含回答全文与召回来源，可按地市导出）**；
   - **RAG 审计**：检索型轮次的召回明细（RRF 融合名次/得分/被重排丢弃者）+ 来源清单；**质检标记**
     （召回不准/答案有误/知识过旧/其他 + 备注）驱动闭环——**一键把该轮 QA 预填为知识库新条目**入库生效，
     已打标轮次可导出 badcase 清单（存量历史轮次无召回明细，自功能上线起积累）；
     门户每轮回答可**点赞/差评+修改意见**，反馈汇入差评关联口径（列表过滤/知识命中报表"用户差评"列/badcase 导出），与质检标记互补；
     **知识命中报表**页签按知识条目聚合：被召回轮次/平均名次与得分/保留率/**差评关联率**——
     定位"常被召回却常被判差"的低质量知识与从未被召回的闲置知识，支持机构/类型/主题/时间过滤与 xlsx 导出；
   - **知识库**：新增一条知识 → 自动切块+向量化+写 ES → 回门户提问立即命中；「全量对账」演示库与索引双向修复；
   - **流程实例**：时间/机构/状态过滤 + 数据导出（含受理单号与脱敏变量摘要；地市账号仅见本地市数据）；
   - **权限体系**：用户/角色/部门/菜单管理（RBAC 真实 CRUD；用 admin 登录可见全部机构，fzzx 只读本机构及以下）。
9. **工程细节穿插**：
   - `config/app.yml` 里所有敏感值为 `Enc[...]`（SM4-CTR）——把明文填回去重启，观察**自动加密回写**；
   - `python -m app.core.config_cli 新密码` 一键生成 Java 同款密文；
   - 门户问答不落任何 trace 表：**轮次表+阶段表**即完整审计流水（一表贯通模型/检索/工具行）。

## 六、与既有系统的迁移关系

| 维度 | 原架构 | 本演示 |
|---|---|---|
| 服务形态 | Java 编排层(9309) + Python 原子层(15002) | 单 Python 服务（编排+原子能力合一，LangGraph 承载编排） |
| 口令协议 | SM3 `$1a` 双重摘要 + 前端摘要传输 | **逐位一致**（同一密文互认） |
| 配置加密 | Java DecryptConfig + SM4-CTR `Enc[...]` | 同算法同密钥，**密文互认**，并支持明文自动升级回写 |
| 检索 | ES BM25+kNN → RRF → rerank | 同管线（jieba 预分词字段承载词级 BM25） |
| 审计 | 独立 trace 表 + 观测接口 | 轮次表 + 阶段表收敛（阶段即登记，管理端直接消费） |
| 权限 | 若依 RBAC + dept_no 数据轴 | 同语义精简（6 表），读范围/可写集分离 |

## 七、对外开放接口（Open API）

面向外部系统的第二条服务入口（与门户共用同一问答管线，见 `CONTEXT.md` 术语表）：

- **鉴权**：请求头 `X-API-Key` → 接入方（`open_client` 表，绑定归属租户）；无 Key 401、停用 403、参数错 422。演示 Key：`sk-open-demo0123456789abcdef0123456789`
- **三要素外部传递**：`id_card`（必填，18 位）/ `name` / `phone` 随请求传入，工具查询自动注入、结果脱敏；`auth_ticket` 为预留授权字段（仅落审计）
- **跨租户区域路由**：归属租户=接入方绑定机构；问题提及其它城市时检索自动切换到该城市机构（本机构全量∪其祖先链公开），检索租户不可显式指定；外地区（无对应机构）走联网检索
- **问题溯源**：`X-Source-System` / `X-Trace-Id` 请求头透传落 `turn`（source_type=open / open_client_id / source_system / trace_id），TraceId 缺省系统生成并回写响应头；审计接口按 TraceId 反查
- **会话延续**：`conversation_id` 由外部传递（首答响应返回，续问回传，仅限本接入方会话）

| 接口 | 说明 |
|---|---|
| `POST /api/open/v1/chat/stream` | SSE 流式问答（事件协议与门户一致） |
| `POST /api/open/v1/chat/ask` | 同步问答（一次性返回全文+来源+推荐，响应头带 X-Trace-Id） |
| `POST /api/open/v1/account/query` | 账户数据查询（balance/loan/deposit，即 MCP 工具 HTTP 形态，返回脱敏） |
| `GET /api/open/v1/knowledge` | 公开知识查询（仅 is_public=1，支持 dept_no/theme/q 过滤） |
| `GET /api/open/v1/turns` | 轮次审计查询（限本接入方，支持 trace_id 过滤） |

演示：

```bash
curl -X POST http://127.0.0.1:9310/api/open/v1/chat/ask \
  -H "X-API-Key: sk-open-demo0123456789abcdef0123456789" \
  -H "X-Source-System: erp-demo" -H "X-Trace-Id: demo-001" \
  -H "Content-Type: application/json" \
  -d '{"question":"福州公积金贷款最高能贷多少","id_card":"350001199002022345"}'
```

验收：`scripts/integrity_check.py` 第 15-19 项（无 Key 拒绝 / 三要素校验 / 区域路由 / 脱敏 / trace 落库）。
**完整接口文档（含全部实测数据示例）见 [docs/open-api.md](docs/open-api.md)**。
边界（演示口径）：Key 与三要素明文传输仅适用于内网/演示，生产需 HTTPS + Key 哈希存储 + 限流；授权凭据 `auth_ticket` 未做实名核验。

## 八、已知边界（演示口径）

- MCP 工具的业务数据为**确定性演示生成器**产出（按证件号哈希），未接真实业务库；
- 停止/取消的跨实例信号走 Redis（本机可缺省，退化为进程内取消）；
- 材料快照存于轮次表与进程内（不单独建快照存储，演示口径已够）；
- 重排接口不可用时自动回退融合序，不阻塞回答（设计语义，非缺陷）；
- 联网检索默认走本仓自建服务（Bing/搜狗引擎可达性依网络环境而定；DuckDuckGo 引擎在部分网络不可达，服务会自动跳过并记录 engine_errors）；
- 流程自动节点当前注册 3 个动作（复用 MCP 工具实现），新增动作 = FLOW_ACTIONS 注册 + 流程定义 JSON。
