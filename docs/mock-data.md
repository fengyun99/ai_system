## 二·五、模型供应商（2026-09-24 收敛）

模型配置已收敛为 **DeepSeek 单一供应商**（`config/model-config.json`）：
- `deepseek`：对话/意图/判官/生成（api.deepseek.com，模型 deepseek-v4-pro）；
- `embeddings`：向量化（同 DeepSeek key 与端点；若 DeepSeek 平台不提供 embeddings，将本条目改指任一向量服务并重跑 `scripts/init_db.py` 重建索引）；
- 原 qwen/qwen-max/zhipu/kimi 条目及 dashscope key 已全部删除（key 均已失效）；
- 重排（rerank）随 qwen key 一并移除——检索链按设计**自动回退 RRF 融合序**，不阻塞回答；
- 换 key：直接把有效 DeepSeek key 明文填入 `model-config.json` 的 `api_key` 数组，首次启动自动加密为 `Enc[...]`。

## 三、MCP 工具数据（问答/查询场景）

`app/rag/tools.py` 中的三个工具为**确定性生成器**：以身份证号做 MD5 哈希取模，
生成稳定的余额/贷款/缴存明细（同一身份证号每次查询结果一致）。结果中的证件号、卡号**前3后4脱敏**。

| 工具 | 说明 |
|---|---|
| `query_account_balance` | 账户状态/余额/缴存月数（8千-40万区间按哈希生成） |
| `query_loan_info` | 贷款总额/剩余本金/利率/期数（1/3 概率无贷款记录） |
| `query_deposit_detail` | 近 N 月缴存明细 |

> 注意：MCP 工具面面向**问答**，由大模型发现/调用；与下面「办理流程」的校验数据**互不复用**（两套数据源刻意分离）。

### 4.2 字段校验规则与报错文案（提交时后端校验，前端表单字段下红色提示，**不推进下一步**）

流程展示约定：步骤进度按**用户交互步**计（填表/确认，系统自动节点不计数）；
结束后展示"最后一态的表单数据"（办理信息/信息确认/办理结果三段），历史回看同形态；
卡号/证件号/手机号在一切展示面（表单回显/确认摘要/最终表单/审计）均为**脱敏形态**。

表单字段（按流程定义）：

| 节点 | 字段 | 说明 |
|---|---|---|
| 1/7 填写提取信息 | 提取原因（下拉）、提取金额（数字） | 金额受绑定账户余额约束 |
| 2/7 填写收款账户 | 本人一类银行卡号 | 须为该登录用户名下登记卡 |

校验规则：

| 字段 | 规则 | 错误示例 | 报错文案 |
|---|---|---|---|
| 银行卡号 | 16-19 位数字 | `1234` | 银行卡号应为 16-19 位数字，请检查后重新填写 |
| 银行卡号 | 须为该身份证号名下登记卡 | `6222020000000000000` | 卡号与缴存人 陈测试 的登记账户不一致（演示：请使用本人名下 I 类卡，见 mock 数据文档） |
| 提取金额 | 数字且 > 0 | `0` / `abc` | 提取金额必须大于 0 / 金额必须为数字 |
| 提取金额 | ≤ 账户余额 | 对 fzzx（陈测试）填 `500000` | 提取金额超过账户余额（当前可提取 394,550.00 元） |

> 身份证号不再是表单字段（由登录态注入）；上述"卡号与缴存人不一致""金额超余额"两条校验
> 均以**当前登录用户的绑定账户**为基准。

## 五、联网检索服务 Mock 边界

`search_service` 为自建服务（Bing + 搜狗聚合），结果为**真实公网检索**，非 mock；
网络不可达时该路径降级为拒答（文案见下），DuckDuckGo 引擎在国内网络通常不可达，服务会自动跳过。

## 六、拒答与转人工（演示文案）

- 知识不足且联网未命中/关闭：**当前内容暂时不支持回答** + 引导转人工（右下角 🎧 入口，落 `intent=handoff` 审计）；
- 与公积金无关的实质问题：**只能回答与住房公积金相关的问题**；
- 外地区且联网不可用：提示仅支持福建省内业务 + 转人工。

## 七、替换为真实系统的接入点

| Mock 位置 | 替换方式 |
|---|---|
| `app/mock_data.py`（`USER_BINDINGS` + `MOCK_ACCOUNTS`） | 改为身份中台/账户系统查询（登录后按 user_name 解析真实身份证号；查询与办理均按此取数） |
| `app/biz_service.py` 的校验函数 / `FLOW_ACTIONS` | 改为调用真实业务系统接口（函数签名不变即可，流程引擎无需改动） |
| `app/rag/tools.py` 的工具实现 | 替换为真实业务查询接口（MCP 服务端注册名不变，Agent 侧零改动） |
| 知识库种子 | 管理端录入真实政策知识（或批量导入） |
| `search_service` | 可整体替换为 docker 版真 SearXNG，仅改 `config/app.yml` 的 `websearch.base_url` |
