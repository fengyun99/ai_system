# 入库计量独立登记（ingest_log），不造 system 轮次

知识入库向量化消耗 embedding token，但入库不是对话轮次（TokenMeter 是每轮一个、
随轮落库的），这笔消耗此前完全丢弃。决定新建独立的入库计量流水：每次入库（成功或
失败）登记一行——知识条目、切块数、token（真值/估算口径）、耗时、结果与错误、
操作者。理由：入库是领域事件，与"一问一答"的轮次语义不同（没有意图/召回/反馈等
维度），混入轮次表会污染审计语义；单独成表还能顺带补齐入库耗时与失败审计，与
知识命中报表形成成本-收益对照。

## 后果

- 入库消耗与轮次消耗分开聚合，仪表盘分别呈现（"问答花了多少"与"养知识库花了多少"
  是两笔账）。
- 入库计量的 token 口径与轮次一致（真值优先、字符估算兜底并标记 estimated）。

## 备选方案（已否）

- 造 system 性质轮次挂 turn_stage——轮次表的意图/召回/反馈等列全部不适用，且会
  混入轮次统计口径。
- 只进仪表盘聚合、不落明细——回答不了"这次入库烧了多少、失败在哪一步"。
